# Vexryn 0.2 — catalogue, dangerous combinations, tool traps, every agent's load, accepted findings

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (founder's choice: inline, no subagents; final review = `/code-review high` in session). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the gaps listed to the founder on 2026-09-26: (1) traps hidden in tool descriptions, (2) dangerous combinations of powers, (3) a measured, open catalogue of popular MCP servers so the PR review can say "adds 8 tools that can send messages" from the config alone, (4) the catalogue used everywhere (scan, review, MCP tools) plus "deprecated by its publisher", (5) the always-loaded context of Cursor, Windsurf and Gemini CLI, (6) accepted findings a team can silence, (7) the HTML report brought level, (8) release 0.2.0.

**Architecture:** Every new fact is computed by a pure function from data we already hold (tool lists from `--deep`, the local store or the catalogue; config files on disk or in git objects). The catalogue is a JSON file shipped in the npm package, produced ONLY by a public GitHub Actions job (ephemeral VM, no secrets, read-only token) that launches each package with dummy credentials, never on a user's or founder's machine. Descriptions are never stored in the catalogue or returned to an agent (a poisoned description must not be relayed); only facts are.

**Tech Stack:** TypeScript/Node, `node:assert` tests under `test/`, GitHub Actions. No new dependency.

**Spec:** `docs/research/2026-09-24-innovation-mining.md` §1 (catalogue), §2 takes 3–4 and 9 (traps in live descriptions), §3 takes 4–5 (accepted findings, toxic flows), §4 take 2 (profiles), §5 (Waves B–C); founder decisions 2026-09-26: "on met en place tout ce qui manque"; catalogue = popular servers, measured by us, published openly.

## Global Constraints

- Facts, not verdicts: "contains the phrase …", "can send messages", "marked deprecated by its publisher". Unsure → nothing.
- A figure always says where it comes from: *measured here <date>* or *Vexryn catalogue, pkg@version, measured <date>*.
- The catalogue is filled only by the public workflow; never by hand, never from a package name alone.
- Nothing new is executed on the static path; nothing is sent; no LLM; no new dependency.
- Every repo/package string rendered through `code()` (review) or `plain()` (terminal).
- `mcp-check` invariants hold: every exposed tool read-only, no name/description containing wire/trim/wrap/deep/write.
- Tests never touch the real home (`VEXRYN_HOME`).

## Deliberately out of this plan (said to the founder)

- **Proof of exploitability (step 3):** its own design session — it drives the user's real agent and model, which needs decisions on cost, consent and sandbox.
- **Profiles** (mcpm): no evidence anyone needs them; clients now load tools on demand. Revisit on a user request.
- **Wiring user-wide configs:** stays read-only (Claude Code rewrites `~/.claude.json` while running).
- **Codex CLI** as a client: not in this plan; next candidate.

## Review Focus

1. A pinned version absent from the catalogue must never borrow another version's figures (Task 4 test).
2. A PR that edits `.vexryn.json` must not silence its own findings: acceptances are read from the BASE side only (Task 6 test).
3. A poisoned tool description must never reach the terminal raw or an agent at all — flags only (Tasks 1, 4 tests).
4. An agent with no MCP servers but always-on rules (e.g. Cursor rules only) still gets its own section (Task 5 test).
5. `unpinned()` behaviour of the review is unchanged after the package parser moves (existing diff tests stay green).

### Task 3: the measured catalogue (production)

**Files:** Create `catalog/servers.json` (what to measure: `{ "npm:<pkg>" | "pypi:<pkg>": { args?: string[], env?: string[] } }`), `scripts/measure-catalog.mjs`, `.github/workflows/catalog.yml`, `catalog/catalog.json` (output, committed); Modify `src/scan/introspect.ts` (`introspectServer(server, timeoutMs?, env?)`), `package.json` (`files` += `catalog/catalog.json`).
**Catalogue format:** `{ schema: 1, servers: { "npm:<pkg>": { deprecated: string|null, latest: string, versions: { "<ver>": { measuredAt, by, tools: [{ name, tokens, power, hash, flags? }] } } } } }` — no descriptions.
**Script:** for each entry: resolve latest version (`npm view <pkg> version`/PyPI JSON), deprecation (`npm view <pkg> deprecated`), launch `npx -y <pkg>@<ver> …args` or `uvx <pkg>==<ver> …args` with each listed env name set to `not-a-real-value`, 120 s timeout; merge into the existing catalogue (older versions kept); print a table measured/failed. `by` = the run URL from `GITHUB_SERVER_URL/GITHUB_REPOSITORY/actions/runs/GITHUB_RUN_ID`. Refuses to run outside GitHub Actions unless `--local-ok` (never on a person's machine by accident).
**Workflow:** `workflow_dispatch` only; `permissions: contents: read`; ubuntu; pinned checkout; `pipx install uv`; `npm ci --ignore-scripts && npm run build`; run script; upload `catalog/catalog.json` as artifact. A human downloads it and commits (the Vexryn review then shows the change).

- [ ] Commit script + list + workflow, push to main, dispatch, download artifact, commit `catalog/catalog.json` with the run URL in the message. Unit check: `test/catalog-check.mjs` validates the shipped file's shape (every tool has name/tokens/hash; no `description` key anywhere; every version has `by` starting with `https://github.com/`).
