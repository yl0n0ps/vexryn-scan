# Marche 2 — PR review of agent configs: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `vexryn diff --base <ref> [--head <ref>]` turns a PR's agent-config changes into one exact, readable markdown comment, and a composite GitHub Action posts it as a sticky, non-blocking PR comment.

**Architecture:** Each side of the diff is materialized from git objects into a temp dir (only agent-config paths), then read by the existing static scan pieces (`parseServers`, `claudeCodeContext`) plus a new Claude Code settings reader. Two snapshots are compared into markdown lines; every untrusted string goes through one `code()` helper. The Action is a thin shell around the CLI + `gh api`.

**Tech Stack:** TypeScript/Node ≥18, git CLI, `gh` CLI (Action only). Tests are plain `node:assert` scripts under `test/` run by `npm test`.

**Spec:** `docs/specs/2026-09-24-pr-review-design.md`

## Global Constraints

- Static only: never execute anything read from the repo; git blobs are read with `git show`, never checked out.
- Exact facts only: no guessed tool lists or invented numbers.
- Never print env/header values — names only.
- No new runtime dependency.
- Output is always markdown starting with `<!-- vexryn-pr-review -->`; the no-change body is exactly `No agent config change.`
- Exit 0 on success (non-blocking); 2 on usage error; 1 on git failure.

## Review Focus

1. Markdown/@mention injection through server names, commands, skill names, paths → rendered inert inside code spans (Task 3 test).
2. Secret env/header values in configs → never appear in output (Task 3 test).
3. A config file broken in the PR (invalid JSON) → reported as unreadable, not as "all servers removed" (Task 3 test).
4. Very large PRs (dozens of servers) → sections capped, comment stays under GitHub's 65 536-char limit (Task 3 test).
5. Bad refs (unknown, option-looking like `--output=x`, non-git dir) → clear error, non-zero exit, nothing written (Task 1 + Task 3 tests).
